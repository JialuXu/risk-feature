# risk-feature-pipeline 产物列字典

本文件是所有 Level 1 / Level 2 落盘 CSV 的列字典权威来源。**写消费代码时以此为准，不要猜列名。**

A4 后对外列名已统一为「特征 / 分群维度 / 分群名称」三件套；旧 CSV 中的 `特征名称` / `分群值` 在 `risk_result_query.load_results()` 读取时会被自动 rename，但直接 `pd.read_csv` 老文件时会看到旧名。

---

## Level 1 · `data/results/<project>/`

### `<project>_IV分析结果_全量.csv` ⭐ A5 新名

全量样本（不分群）的 IV 排名。

| 列 | 类型 | 说明 |
|---|---|---|
| `特征` | str | 特征列名 |
| `特征类型` | str | 原始 / 衍生 |
| `IV值` | float | 全量 IV |
| `预测能力` | str | 强 / 中等 / 弱 / 无预测能力 / 过强 |
| `IV可信度` | str | 可信 / 参考 / 不可信-* |
| `总样本数` | int | |
| `总坏客户数` | int | |

> 兼容副本 `<project>_IV分析结果.csv` 内容相同，下一个版本会移除。

---

### `<project>_IV分析结果_分群.csv` ⭐ A5 新名

| 列 | 类型 | 说明 |
|---|---|---|
| `分群维度` | str | 例如 `企业规模` |

| `样本数` | int | 该分群总样本 |
| `坏客户数` | int | 该分群坏客户数 |
| `坏客户率` | float | |
| `特征` | str | 特征列名 |
| `IV值` | float | 该分群 IV |
| `IV可信度` | str | |

> 兼容副本 `<project>_IV值分析.csv` 内容相同，下一个版本会移除。

### `<project>_IV值透视表.csv` / `<project>_IV可信度透视表.csv`

`分群名称` × `特征` 的透视宽表。

### `<project>_风险规则表.csv`（仅 `analyze --steps rules` 后存在）

每行一条决策树规则。

| 列 | 说明 |
|---|---|
| `分群维度` | 全样本时填 `'全样本'` |
| `分群名称` | 全样本时填 `'全样本'`（**A4 前叫** `分群值`） |
| `规则条件` | 文本化条件，如 `资产负债率 > 0.7501 且 现金比率 <= 0.12` |
| `涉及特征` | 列表字符串（顿号分隔），如 `资产负债率、现金比率` |
| `特征数量` | rule 深度 |
| `覆盖样本数` / `覆盖率` | |
| `覆盖坏客户数` / `规则坏账率` / `整体坏账率` | |
| `Lift` | bad_rate / overall_bad_rate（测试集口径） |
| `训练集Lift` | 同一规则在训练集上的 Lift，对照乐观偏差 |
| `坏账率下界` / `坏账率上界` | 95% CI |
| `稳定性坏账率均值` / `稳定性坏账率标准差` / `稳定性有效次数` / `稳定性重抽样次数` | 测试集 bootstrap 重抽样稳定性（有效 = 命中坏客户 ≥ min_bad_in_leaf）；旧版为 `CV坏账率均值` / `CV坏账率标准差` / `CV有效折数`（样本内 5 折，已废弃） |
| `稳定性等级` | 有效占比 < 0.6 → 不稳定；否则按坏账率变异系数 ≤0.20 稳定 / ≤0.40 较稳定 / 其余不稳定 |
| `评估口径` | `样本外(留出30%)`；坏客户不足时为 `样本内(坏客户不足未留出)`，结论偏乐观 |
| `建议用途` | 审批红线 / 关注线 / 参考 |

## Level 2 · `output/<project>/` ／ `data/results/<project>/`（trigger 输出）

### `<project>_风险触碰明细_宽表.csv`

每行一个客户。

| 列 | 说明 |
|---|---|
| `<id_col>` | 主键（默认 `客户编号`） |
| `<info_cols>` | 业务元信息（行业/规模/分行 等，仅在宽表本身含这些列时才会存在） |
| `<target_col>` | 默认 `is_bad` |
| `<特征>_值` | 该特征的原始数值 |
| `<特征>_触碰` | 1=触碰 / 0=未触碰 / NaN=数据缺失 |
| `触碰特征总数` | int |
| `IV加权风险得分` | 0–100，越高风险越大 |
| `触碰特征清单` | 触碰特征名称（分号分隔） |
| `触碰数_<类别前缀>` | 各业务类别下的触碰数 |

### `<project>_风险触碰明细_长表.csv`

只保留触碰记录。

| 列 | 说明 |
|---|---|
| `<id_col>` / `<info_cols>` / `<target_col>` | |
| `特征值` | |
| `特征名称` | （此处保留旧名，因长表不参与列名 unify 域） |
| `特征类别` / `全量IV` / `风险方向` / `适用范围` | |
| `触碰阈值` | 文本化，如 `> 0.7` |
| `阈值来源` | `报告明确阈值` / `坏客户均值(样本内…)` / `范围内中位数(*)` |

### `<project>_触碰阈值说明.csv`

每行一个特征的阈值审计。`方向校验`：`一致` / `⚠ 不一致：…`（坏/好客户均值方向与 risk_direction 相反）/ `-`（显式阈值、中位数兜底或跳过）；`触碰条件=(已跳过)` 表示 scope 维度列不存在。

## 列名 unify 兼容矩阵

| 旧列名 | 新列名 | 自动 rename 域 |
|---|---|---|
| `特征名称` | `特征` | `_save()` 写盘 + `load_results()` 读盘 |
| `分群值` | `分群名称` | 同上 |
| 其它列名 | 维持不变 | — |

`risk_trigger_extraction` 的长表保留 `特征名称`（不在 unify 域内，因为它和「触碰特征清单」语义不同，避免误改）。
